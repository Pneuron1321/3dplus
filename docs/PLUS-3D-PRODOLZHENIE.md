## 3. Новая цель: Плюс — аватар VRChat

Александр играет в VRChat **на Quest 3 без компьютера** (эфир идёт со шлема). Значит, аватар должен проходить
**ограничения Quest (Android)**, а не только ПК.

| Ограничение (Quest/Android) | Значение |
|---|---|
| Треугольники | Excellent ≤ 7 500 · **Good ≤ 10 000** · Medium ≤ 15 000 · Poor ≤ 20 000 (Very Poor на Quest по умолчанию скрыт) |
| Размер после сборки | цель 5–8 МБ; больше 10 МБ — не загрузить и не увидеть на Android |
| Шейдеры | только `VRChat/Mobile/*` (Toon Lit, Standard Lite) |
| Unity | 2022.3.22f1 через VRChat Creator Companion (VCC), Avatars SDK 3.10.x |
| Аккаунт | для загрузки нужен ранг доверия не ниже «New User» |
| Загрузка | только из Unity на ПК (Windows или Mac), сборка под Android. Ноутбук с Windows у Александра есть (`docs/NOUTBUK-21-10.md` в quest-claude) |

Источники: [Quest Content Optimization](https://creators.vrchat.com/platforms/android/quest-content-optimization),
[Avatar Performance Ranking](https://wiki.vrchat.com/wiki/Avatar_Performance_Ranking), [VRChat SDK](https://wiki.vrchat.com/wiki/SDK).

Сейчас у модели **164 тыс. треугольников, облегчённая — 64 тыс.** Это в 6–16 раз больше «Good» для Quest.

## 4. Разбор плана Gemini (картинка)

| Шаг Gemini | Оценка |
|---|---|
| Сырая → «моделирование высокого разрешения, сглаживание» | **Мимо цели.** Quest требует ≤ 10 тыс. треугольников, а не high-poly. Сглаживание кирпичей убивает стиль |
| UV-развёртка и PBR-текстуры | **Лишнее.** У кирпичной фигурки плоские цвета. PBR (металл, шероховатость, нормали) — память и шейдеры, которых на Quest нет. Нужна палитра (см. ⚿) |
| Детализация, финальные текстуры | частично: детали шипов и щелей — запечь в маленькую текстуру или нормаль, не в геометрию |
| Unity: импорт и настройка | **Верно**, это твёрдая стена: Unity 2022.3.22f1 + VCC на ПК |
| Риггинг и веса «тепловой картой» | **Лишнее для робота.** Детали жёсткие, каждая уже привязана к своей кости (`pixel-mech-rig.glb`). Веса = 1 к одной кости. Гуманоидная разметка Unity ляжет на готовые имена костей |
| VRChat SDK: Avatar Descriptor | **Верно**, но поля на картинке выдуманы. Нужно: точка взгляда (между очками), визем-режим (рот), моргание (Eye Look), PhysBones (антенны пришельца, если надо) |
| Проверка: «Performance: Good» | **Невозможно** с такой сеткой. Без снижения до ~10 тыс. будет Very Poor и на Quest его не увидят |

Чего у Gemini нет вовсе: ограничений Quest, сборки под Android, виземов (рот при речи), моргания, меню выражений
(улыбка, присед), запасного (fallback) аватара, проверки на шлеме.

## 5. Прогон: Глубокий Транзитор + Фарватер ∿ + Отмычка ⚿

Козырь, созданный 29.10, называется **«Отмычка» (⚿)**: `shlem/skills/otmychka/` в quest-claude (зеркало — `shlem2/`
в 3dplus). Глубокий Транзитор и Фарватер — `shlem/deep-transitor.md`, `shlem/farvater.md`.

**⚿ 1 · Боль.** Надеть шлем, зайти в VRChat — и быть Плюсом: узнаваемый, чистые цвета, рот двигается, когда говоришь,
моргает. Его видят все, в том числе на Quest. И без недели ручного 3D-моделирования.

**⚿ 2 · Транзитор по ограничениям.**

| Ограничение | Тип | Чтение |
|---|---|---|
| ≤ 10 тыс. треугольников, ≤ 10 МБ, мобильные шейдеры | **твёрдое** | держим строже всего: цель 7,5–10 тыс. |
| Загрузка через Unity на ПК | **твёрдое** | один раз на ноутбуке; всё до этого готовим в облаке |
| «Нужна high-poly модель» (Gemini) | **тень** | Quest её не покажет |
| «Нужны UV и PBR-текстуры» | **тень** | плоский цвет = палитра |
| «Нужен риггинг с весами» | **тень** | робот жёсткий, кости уже есть |
| «Нужно лепить заново (сетка генератора)» | **тень** | пятнистая каша; у нас есть генератор с точными цветами и деталями |
| Похоже на листы Александра | стандарт | мера по деталям, наложение (`MODELIST-TRANZITOR.md`) |
| Шипы на каждом кирпиче | стандарт | на Quest — только крупные видимые, остальное — текстура |

**⚿ 3 · Избыток.** (а) `src/pixel-mech.js` знает про **каждый** кирпич его цвет, деталь и кость. (б) Скелет из 20
гуманоидных костей уже есть. (в) Мимика уже нарисована 2D — моргание, улыбка, рот. (г) Облако (GitHub Actions)
бесплатно для открытого репо: там можно запускать Blender, а может быть, и Unity. (д) Blender работает как
библиотека Python (`bpy`), без окна.

**⚿ 4 · Семь отмычек.**
- **Ноль:** не лепить заново. Аватар = тот же генератор с бюджетом Quest (`--opt=vrc=1`).
- **Площадь:** шипы, по прикидке, — большая часть треугольников (точно — шаг 1 плана). Убрать шипы с невидимых граней. Видимые сделать 6-гранными
  или нарисовать на текстуре. Соседние кирпичи одного цвета склеить в одну грань (жадное слияние).
- **Рецепт:** цвет — не краска по точкам, а **палитра 32×32 пикселя**. Каждая грань смотрит UV-координатой в свою
  клетку цвета: 1 материал, 1 крошечная текстура, идеально чистые цвета, никаких пятен.
- **Слой ниже:** рот и глаза — не геометрия, а **смена текстуры лица** (атлас кадров: улыбка, рот открыт A/O/E,
  моргание). Виземы VRChat — ключи формы (blendshapes), которые меняют UV лица на нужный кадр. 2D-кадры у нас уже есть.
- **Повтор:** кости и привязку взять из `pixel-mech-rig.glb`. Гуманоидная разметка Unity — по готовым именам.
- **Время:** всё до Unity — в облаке (Blender `bpy` в GitHub Actions): GLB → FBX с палитрой, виземами,
  проверкой треугольников. Александру — один готовый `.unitypackage`.
- **Инверсия:** не «сжимать большую», а «строить маленькую и добавлять детали, пока есть бюджет»: счётчик
  треугольников в сборке, детали по приоритету (лицо, очки, пришелец, кисти, тапочки…).

**∿ 5 · Фарватер.**

| Идея | Z (польза) | X (цена, риск) | Слой | Отделяется? |
|---|---|---|---|---|
| Генератор с бюджетом Quest | точные формы и цвета, один источник | работа в `pixel-mech.js` | геометрия | да |
| Палитра 32×32 | чистые цвета, 1 материал, ~2 КБ | UV по клеткам в генераторе | материал | да |
| Лицо — атлас кадров + виземы | рот и моргание как в эфире | ключи формы на UV лица | мимика | да |
| Кости из rig-GLB | ноль ручной работы | проверить гуманоидную разметку Unity | скелет | да |
| Blender в облаке | Александр получает готовый пакет | настройка workflow | конвейер | да |
| Unity в облаке (game-ci) | без ноутбука до загрузки | лицензия Unity Personal в секретах; загрузка в VRChat всё равно из Unity с входом | сборка | частично |
| Сетка генератора 3D (telo=setka) | органика | пятна, 100 тыс.+ треугольников | — | **нет — отбой для аватара** |

**6 · Глубокий разбор.**

| Путь | Треуг. | Чистота цвета | Время | Риск |
|---|---|---|---|---|
| План Gemini (high-poly + PBR + ручной риг) | 100 тыс.+ → не Quest | хорошая | недели | Very Poor, на Quest не виден |
| telo=setka → упрощение | 10 тыс. | пятна | дни | узнаваемость |
| **⚿ Генератор с бюджетом + палитра + атлас лица** | **7,5–10 тыс.** | **идеальная** | **2–4 сессии** | шипы в текстуре — проверить на глаз |

Худшие случаи: (1) не влезаем в 10 тыс. — сначала уходят шипы, потом скосы, потом мелкие кирпичи, а детали
лица остаются. (2) Unity не видит гуманоид — правка имён и ориентации костей в `bpy`. (3) Виземы «дёргаются» —
меньше кадров, только A, O и закрыто. (4) Аккаунт Александра в ранге «Visitor» — нужно поиграть до «New User».
Сделано, но будто не сделано: аватар загружен, но рейтинг Very Poor, и на Quest его видят серым роботом. Защита:
счётчик треугольников и размера в сборке и проверка рейтинга в SDK до «одобряю».

**7 · Синтез — «Плюс-аватар из того же генератора».**
1. `--opt=vrc=1` в `pixel-mech.js`: жадное слияние граней, шипы только на видимом и низкополигональные, бюджет
   ≤ 10 тыс. со счётчиком; UV каждой грани — в клетку палитры; лицо — отдельная плоскость с UV на атлас кадров.
2. `tools/vrc/` (Blender `bpy`): GLB → FBX, кости из rig-GLB, ключи формы виземов (`vrc.v_sil`, `v_aa`, `v_oh`,
   `v_ee`… — кадры атласа) и моргание, проверка (треугольники, материалы, кости, размер).
3. Облако: workflow `vrc.yml` собирает `plus-vrc.fbx` + `palitra.png` + `lico-atlas.png` + `.unitypackage`
   (если подключим game-ci) → выпуск.
4. Александр на ноутбуке: VCC → проект аватара → импорт пакета → Avatar Descriptor уже настроен → «Build & Publish
   for Android» (и для ПК).
5. **Первая проба:** вид спереди, 3/4 и сбоку низкополигональной версии рядом с v6 + число треугольников. Это
   наложение на листы показать Александру.
6. **Откат:** флаг выключен — модель по умолчанию не тронута.
7. **Δ против Gemini:** в 10–16 раз меньше треугольников, ноль ручной UV и весов, мимика как в эфире, проходит Quest.

## 7. Ответы Александра (30.10) — они важнее раздела 5

4. **Улыбка** как анимация аватара, **моргание**, возможно **покачивание пришельца**.
5. **И Quest, и ПК**.

### Поправка синтеза ⚿ под ответы: форма — с сетки, цвет — с кирпичной v6

Форма telo=setka Александра устраивает, плохой только цвет. Отмычка «Повтор + Рецепт»: **цвет не рисуем заново, а
переносим с кирпичной v6**. В v6 у каждого кирпича чистый цвет палитры, и стоит он в правильном месте (лист 1 и 2).
1. Совместить v6 и telo=setka: масштаб и сдвиг по силуэту, ICP (`trimesh`). Ноги «утка» и тапки — свои пары.
2. Каждому треугольнику сетки — цвет **ближайшего кирпича v6** (не точки листа). Детали берут ровно палитру, без «каши».
3. Сгладить границы: голосование соседей (у каждого треугольника — цвет большинства в радиусе), острова меньше N — в соседа.
4. Лицо, визор и улыбка — по разметке листа (уже есть в `telo_raskraska.py`), поверх.
5. Мера: ΔE и совпадение по деталям с листом тела **до и после** — показать Александру наложение. Цель ≥ 80 % по деталям.
6. Где v6 и лист расходятся (тапочки «Пикколо» — мятные, ноги «утка») — цвет с листа ног `nogi-tapki-list.png`
   по маске детали.

**Бюджет и платформы — один проект Unity, две сборки под одним ID аватара:**
- **Quest (Android):** ≤ 10 тыс. треугольников (Good), шейдер `VRChat/Mobile/Toon Lit`, 1 материал, палитра
  или запечённая текстура 512–1024, ≤ 10 МБ. Сетку упростить (`pymeshlab` quadric decimation / QuadriFlow в Blender),
  цвет — запечь в текстуру по UV (`xatlas`).
- **ПК (Windows):** до 70 тыс. треугольников (Good на ПК), можно Poiyomi/lilToon, текстура 2048, мягкие тени.
  Видят игроки на ПК; на Quest все видят Quest-версию. Эфир Александра идёт с Quest — главное Quest.
- Сборка: «Build & Publish for Android», потом то же для Windows — оба в одном аватаре (один Blueprint ID).

**Тапочки:**
- уменьшить по листу пропорций (`MODELIST-TRANZITOR.md`: длина ≈ 2,6 ширины голени, высота ≈ 0,5 длины);
- отдельная сетка на кости стопы;
- **снять / надеть** — переключатель в меню выражений (VRCFury Toggle или аниматор: объект вкл/выкл), под ними —
  стопа робота (низкая плашка или шарнир);
- «как резиновые» — лёгкое покачивание/сжатие PhysBones на носке; можно сделать «сбросить» — тапок слетает и
  лежит рядом (World Constraint / VRC Drop), это позже.

**Мимика:**
- **моргание** — ключ формы `blink` (визор: глаза-полоски сужаются) → Eye Look / Eyelids в Avatar Descriptor;
- **улыбка** — ключ формы `smile` + жест в меню (VRCFury);
- **рот при речи** — виземы `v_aa`, `v_oh`, `v_ee`, `v_sil`… (ключи формы на губе улыбки);
- **пришелец** — своя кость `Alien` на голове + VRC PhysBone (покачивание, лёгкий вес).
