# PIXEL MECH в Godot и VR (Meta Quest 3)

Модель уже подготовлена для Godot 4.3+: скелет для рэгдолла и анимаций, облегчённая версия для
Quest и паспорт кирпичей, из которого фигурку можно собрать по одному кирпичику. Всё ниже
проверено в Godot 4.3 без окна: скрипты из папки `godot/` импортируют файлы, роняют рэгдолл
на пол и рассыпают фигурку на кирпичи.

## Файлы

| Файл | Для чего | Размер |
|---|---|---|
| `pixel-mech.glb` | модули отдельными узлами (голова, корпус, таз, руки, ноги, ступни) — вьювер, Blender, разобранный вид; единица = 1 см | 6.4 МБ |
| `export/pixel-mech-rig.glb` | скелет из 20 костей, каждая деталь жёстко привязана к своей кости; метры (рост 0.31 м); полная детализация | 11 МБ, 164 тыс. треугольников, 5 сеток |
| `export/pixel-mech-rig-lite.glb` | то же, облегчённое для Quest: без фасок и подложек, шипы с 10 гранями | 4.6 МБ, 64 тыс. треугольников, 5 сеток |
| `export/pixel-mech.bricks.json` | паспорт кирпичей: каждый кирпич и скос, его деталь, центр, размер, цвет, шипы | 228 КБ, 1853 кирпича |
| `godot/pixel_mech_ragdoll.gd` | рэгдолл: коробки коллизий подгоняются по кирпичам каждой кости, суставы с пределами | — |
| `godot/pixel_mech_bricks.gd` | фигурка из отдельных кирпичей-тел, `scatter()` рассыпает её | — |
| `godot/check_ragdoll.gd`, `godot/check_bricks.gd` | проверки без окна (см. «Как проверить») | — |

## Импорт

1. Скопируй GLB в проект Godot 4.3 или новее — импорт срабатывает сам.
2. Цвета кирпичей записаны в вершины. Godot сам включает «Vertex Color → Use as Albedo» (проверено: у всех пяти материалов `vertex_color_use_as_albedo = true`). Линза очков импортируется прозрачной.
3. При импорте Godot может написать `Ignoring face with non-finite normal in LOD generation`. Это его собственный упрощатель LOD: если снять галочку **Meshes → Generate LODs** во вкладке Import, сообщение пропадает (проверено). В самой модели нет вырожденных треугольников и нулевых нормалей — это проверяется при сборке.

**Масштаб.** В генераторе 1 единица = 1 см, шаг шипа 0.8 = 8 мм, как у настоящих кирпичиков. Скелетные GLB записаны в метрах, фигурка стоит 0.31 м — размер коллекционной игрушки на столе. Чтобы сделать персонажа ростом с человека, поставь **Root Scale** ≈ 5–6 в настройках импорта. Физика с крупной фигуркой ведёт себя спокойнее.

## Скелет

Имена костей — из гуманоидного профиля Godot (`SkeletonProfileHumanoid`). Поэтому анимации с гуманоидным скелетом (например, из Mixamo) переносятся через Retarget без ручной разметки. Лево и право считаются со стороны фигурки: она смотрит в +Z, её левая рука — на +X.

| Кость | Что к ней привязано | Точка (м) |
|---|---|---|
| Root | — | 0, 0, 0 |
| Hips | таз с шаровыми гнёздами бёдер | 0, 0.109, 0 |
| Spine | живот, серый и тёмный пояса (всё ниже 14 см) | 0, 0.124, 0 |
| Chest | грудь, плечевые корпуса | 0, 0.140, 0 |
| Neck | шея-штырь | 0, 0.198, 0 |
| Head | голова целиком: лицо, шапка с пришельцем, боковые плиты, очки | 0, 0.205, 0 |
| Left/RightUpperArm | наплечник и локоть | ±0.053, 0.182, 0 |
| Left/RightLowerArm | наруч и кулак | ±0.073, 0.158, 0 |
| Left/RightHand | — (кулак в наруче) | ±0.083, 0.109 |
| Left/RightUpperLeg | бедро и колено | ±0.040, 0.109, 0 |
| Left/RightLowerLeg | голень | ±0.040, 0.070, 0 |
| Left/RightFoot | ступня с манжетом | ±0.042, 0.037 |
| Left/RightToes | — (носок) | ±0.044, 0.009, 0.034 |

## Рэгдолл

1. Добавь в сцену `Node3D` и повесь на него `godot/pixel_mech_ragdoll.gd`.
2. В поле **Mech Scene** укажи `pixel-mech-rig-lite.glb`.
3. `set_ragdoll(true)` — фигурка обмякает и падает, `set_ragdoll(false)` — возвращается в позу. Пробел или Enter переключает.

Скрипт создаёт `PhysicalBoneSimulator3D` и 14 физических костей. Коробку коллизии каждой кости он подгоняет по вершинам её деталей. Пределы суставов берутся из таблицы `SPAN`: шея 20°, плечи 70°, колени 45° и так далее.

Проверка в Godot 4.3: за 4 секунды физика роняет фигурку на пол. Физическая кость головы опускается с 0.205 м до 0.054 м (облегчённая версия) или 0.057 м (полная), таз ложится на пол.

По ходу нашлись две ловушки:
- **Пределы суставов задаются в радианах.** Свойства `joint_constraints/swing_span` и `twist_span` в инспекторе показаны в градусах, но хранятся в радианах. Если записать туда `45`, это 45 радиан, и рэгдолл «взрывается». В скрипте стоит `deg_to_rad`.
- **Столкновения деталей между собой по умолчанию выключены** (`self_collision = false`). У фигурки ростом 31 см встроенная физика GodotPhysics с ними неустойчива: в проверке ступня проваливалась под пол. С полом и миром детали сталкиваются всегда. Для VR лучше Jolt — в Godot 4.4 он встроен, в 4.3 ставится дополнением. С Jolt можно включить `self_collision`.

## Разборка на кирпичики

`export/pixel-mech.bricks.json` — основа для будущей разборки и сборки «как конструктор».

```text
{
  "format": "pixel-mech-bricks/1",
  "units": "1 = 1 см; шаг шипа 0.8 (8 мм); y — вверх, фигурка смотрит в +z",
  "faces": ["+x", "-x", "+y", "-y", "+z", "-z"],
  "counts": { "bricks": …, "slopes": …, "studs": … },
  "parts": { "korpus": { "bone": "Chest", "matrix": [16 чисел, по столбцам] }, … },
  "bricks": [
    { "part": "korpus", "kind": "brick", "cls": "chest", "color": "#dcdddb",
      "c": [x, y, z], "h": [полуразмеры], "studs": [[x, y, z, грань, радиус], …] },
    { "part": "lico", "kind": "slope", "planes": [[nx, ny, nz, d], …], … }
  ]
}
```

- `c` и `h` — центр и полуразмеры кирпича в координатах его детали. Мировое положение: `matrix × c`.
- `slope` — кирпич-скос: коробка, отсечённая плоскостями `n·u ≤ d`, где `u` — координаты в долях полуразмера.
- `studs` — шипы для стыковки: точка на грани и номер грани.

`godot/pixel_mech_bricks.gd` ставит каждый кирпич отдельным `RigidBody3D` с цветом и шипами, а `scatter()` рассыпает фигурку.

Проверка в Godot 4.3: фигурка собирается из 1853 тел ростом 0.30 м. После `scatter()` все кирпичи лежат на полу (самый высокий — на 0.03 м), ни один не провалился.

Это наглядная заготовка, а не готовая система:
- скосы в ней — коробки;
- крепёж (болты, оси, шарниры) в паспорт не входит;
- **физика тяжёлая**: пока 1853 тела лежат кучей, один шаг встроенной GodotPhysics занимал 0.74 с на 4 ядрах сервера проверки. Для реального времени так нельзя — см. пункт 3 плана ниже.

**Дальше по плану:**
1. Стыковка по шипам. У каждого шипа есть точка и грань. Ответные гнёзда — те же точки на противоположной грани соседнего кирпича. Совпадение с допуском около 1 мм даёт «защёлку».
2. Кирпичи в руке VR. Берутся через `XRToolsPickable` из Godot XR Tools. Отпущенный кирпич ищет ближайшее свободное гнездо и встаёт на сетку 8 мм.
3. Производительность на Quest. 1853 отдельных тела и сетки — это 1853 вызова отрисовки и тяжёлая физика. Собранную фигурку лучше рисовать через `MultiMeshInstance3D` (одна сетка на цвет). Телами делать только кирпичи в руке или в полёте, а детали, отломанные целиком, — одним телом на деталь (в паспорте их 18). Jolt обычно лучше справляется с кучей тел, чем встроенный движок, но здесь это не проверялось.

## Производительность на Quest 3

| Вариант | Треугольников | Вершин | Вызовов отрисовки |
|---|---|---|---|
| `pixel-mech-rig.glb` | 164 тыс. | 158 тыс. | 5 |
| `pixel-mech-rig-lite.glb` | 64 тыс. | 68 тыс. | 5 |

Для Quest бери облегчённую версию, рендерер Mobile и MSAA ×2–4. Тень от маленькой фигурки лучше рисовать запечённым пятном, а не тенями в реальном времени.

## Как проверить

```bash
npm run build                       # пересобрать всё, в том числе export/
# скопировать export/*.glb, export/pixel-mech.bricks.json и godot/*.gd в проект Godot, затем:
godot --headless --path <проект> --import
GLB=res://pixel-mech-rig-lite.glb godot --headless --path <проект> --script res://check_ragdoll.gd
godot --headless --path <проект> --script res://check_bricks.gd
```

Без окна Godot в конце может напечатать `Parameter "m" is null … servers/rendering/dummy/storage/mesh_storage.h`. Это заглушка рендера в режиме `--headless`, а не ошибка скриптов. В обычном запуске с окном этих сообщений нет.
