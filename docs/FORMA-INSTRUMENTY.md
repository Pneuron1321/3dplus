# Как читать форму с картинки чётко — Трезубец и Глубокий Транзитор (24.10)

Вопрос Александра: «Разберись, каких инструментов тебе не хватает, чтобы считывать форму чётко с картинки, даже
генерированной». Повод — голова v7 и сапоги «Пикколо»: «форма вообще не похожа».

## Честно: почему форма не та

1. Я **смотрю** на картинку и **придумываю числа** (полуоси шлема, ширина маски, где ухо). Картинка в расчёте не
   участвует, только мои глаза.
2. Мои глаза видят уменьшенное, а меры нет. Ошибку в 30 % по ширине я замечаю только после твоего «не похоже».
3. Я переделываю старую голову (v6) вместо того, чтобы снять форму с листа. Старая форма тянет назад.
4. Детали (козырёк, уши, пришелец, лицо) на листе не отделены друг от друга — я угадываю их границы.
5. У сапог картинка одна, вида сзади и сверху нет, а я строю ступенями по памяти о прежней ступне.

## Ψ · Трезубец

**0 · Ось.** Деталь из кирпичей совпадает с картинкой контур в контур во всех ракурсах, которые есть на картинке.

**1 · Засечка ×3** (что сделала бы с первого раза).
1. Подогнать числа точнее, ещё 5 кругов на глаз.
2. Рендерить крупнее и сравнивать внимательнее.
3. Попросить у Александра вид сверху.

**2 · Карта.**

| Шов (стена) | По обе стороны |
|---|---|
| картинка ↔ мои числа | картинка не входит в расчёт |
| мой глаз ↔ рендер | нет меры, только «похоже/не похоже» |
| деталь ↔ деталь на картинке | границы козырька, уха, лица не выделены |
| лист ↔ лист | генерированные виды противоречат друг другу |
| одна картинка ↔ объём | у сапог нет вида сзади и сверху |

| Избыток (есть, но не используется) |
|---|
| на листе головы **5 ортогональных видов и размеры в мм** (70 × 60 × 85) — этого хватает, чтобы вычислить объём |
| у кирпичной детали плоские цвета: фиолетовый, красный, жёлтый, оранжевый, белый, серый — детали разделяются по цвету |
| генератор `Vox` строит кирпичи из **любой** сетки занятости, не только из моих формул |
| Hugging Face открыт и есть `HF_TOKEN`: работают Hunyuan3D-2.1, InstantMesh, MoGe; модели SAM2 и Depth Anything V2 Large скачиваются |
| конвейер рендера даёт те же ракурсы, что на листе, за 15 секунд |

**3 · Зубья.**

**I · Шов «картинка ↔ числа» — форму вычисляет картинка, а не я.**
Из пяти видов листа снять силуэты и пересечь их (оболочка по видам) прямо в сетке шипов (0.8 × 0.512 × 0.8),
масштаб — по размерам в мм. Цвет каждой клетки — с видов, в которых её видно. Получится сетка занятости, которую
`Vox` превращает в кирпичи. Мои числа исчезают.
*Дыра:* впадины, которых не видно ни на одном силуэте (глазницы, щель рта), оболочка не ловит. Их добавляет зуб II.

**II · Шов «деталь ↔ деталь» — разрезать картинку на детали.**
У кирпичных листов детали различаются по цвету, поэтому хватит кластеризации цвета: козырёк, лицо, уши, пришелец,
купол, борта шлема. Для сложных картинок есть SAM2 (сегментация по щелчку). Каждая деталь получает свою оболочку
и рамку в шипах: «козырёк 11 шипов × 4 ряда, выступает на 1 шип». Это задание с числами, которые можно проверить.
*Дыра:* полупрозрачный козырёк смешивает цвета — для него нужен порог по красному.

**III · Шов «глаз ↔ рендер» — мера вместо «похоже».**
После каждой сборки рендерить ровно ракурсы листа и считать совпадение силуэтов (IoU) по видам и по деталям, плюс
разницу рамок в шипах. Показывать Александру только то, что прошло порог: силуэт ≥ 0,9 во всех видах, каждая
деталь ≥ 0,8.
*Дыра:* метрика силуэта не видит характер (улыбка, наклон пришельца). Глаза Александра остаются последней проверкой.

**Ересь (для одной картинки, как сапоги).** Рамка засечек — «объём строю я». Отрицание: **объём строит генератор,
я перевожу его в кирпичи.** Hunyuan3D-2.1 или InstantMesh по картинке сапога → сетка → она же как сетка занятости
(вокселизация в шипах) → `Vox` → кирпичи. Подошва, ворот и складки — из сетки, цвета — с картинки.
*Дыра:* генератор додумывает невидимую сторону. Для обуви это не страшно: сапоги симметричны, и левый — зеркало правого.

**4 · Перекрёстный Рельсорез.**
I и II — один корень (форма из картинки), они складываются: II даёт детали, I — их объём. III проверяет обоих.
Ересь — другой корень (форма из генератора), для случаев, когда видов меньше двух.
Как «сделано, но не сделано»:
- I — оболочка совпала спереди, а сбоку виды листа противоречат. **Защита:** метрика по каждому виду отдельно;
  противоречия листа выписать Александру, а не замазать.
- Ересь — сетка генератора красивая, а в кирпичах каша. **Защита:** вокселизация с шагом шипа и та же метрика
  против картинки.

**5 · Свёртка.**

| Идея | Цена | Первая проба | Отличие от засечек |
|---|---|---|---|
| I · Оболочка по видам листа → кирпичи | вырезка 5 видов, сетка шипов, проекция цвета | голова v7 из листа без единого моего числа формы | засечки крутят мои числа, здесь их нет |
| II · Детали по цвету | кластеризация, пороги для прозрачного | рамки козырька, лица, ушей, пришельца в шипах | вместо угадывания границ — мера |
| III · Метрика по видам | рендер ракурсов листа, IoU | таблица «вид × деталь» после каждой сборки | вместо «похоже» — число |
| Ересь · Генератор → кирпичи | квота HF (токен есть), вокселизация | сапог «Пикколо» из Hunyuan3D-2.1 | вместо ступенек по памяти — объём по картинке |

## Глубокий Транзитор · стены и маршруты

| Стена | Тип | Маршрут |
|---|---|---|
| «Без нового софта форму не снять» | **ложная** | 5 видов + размеры = вычислимый объём. Нужен код (оболочка, вокселизация), а не новая программа |
| «Генератор кирпичей понимает только формулы» | **ложная** | `Vox.box(... fn)` уже принимает любую функцию клетки, то есть сетку занятости |
| Глаз на уменьшенных рендерах | настоящая | метрика IoU по видам и деталям (зуб III) |
| Детали не разделены | настоящая, решаемая | цвет-кластеры; SAM2 (модель скачивается с HF) для сложных картинок |
| Генерированный лист противоречив | настоящая | оболочка с допуском, приоритет фронта и бока, список противоречий Александру |
| Одна картинка у обуви | настоящая, решаемая | Hunyuan3D-2.1 / InstantMesh (RUNNING) → вокселизация; MoGe — геометрия с камерой |
| Квота ZeroGPU | **снята** | `HF_TOKEN` в окружении есть |

## Что достать (у Александра)

- Лист головы **без подписей и линеек**, крупнее (сейчас 1254 × 365, на вид ~230 точек), — для чистых силуэтов.
- Если можно — **вид сверху** головы: оболочка по 6 видам точнее.
- Для сапог — ещё **вид сзади или сверху** (тем же генератором), если есть.

## Порядок работы

1. `tools/forma/`: вырезка видов листа → маски деталей по цвету → оболочка в сетке шипов → цвет клеток → данные для `Vox`.
2. Метрика: рендер ракурсов листа и таблица IoU «вид × деталь».
3. Голова v7 из листа — показать с таблицей.
4. Сапог: генератор → вокселизация → кирпичи — показать с таблицей.
